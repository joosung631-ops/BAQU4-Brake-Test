## 카메라 화면 (H.264, 2026-10-23)

2026-10-24: ROS Bag 보기의 카메라는 대시보드 재생 영상만 표시합니다.
재생 카메라는 `/dashboard/bag/camera/...`로 분리하여 실시간 카메라를 함께
실행해도 섞이지 않습니다. ROS 토픽의 실시간/ROS bag 판정 탭은 영상 소스를
변경하지 않습니다. 재생 영상이 없거나 재생이 끝나면 수신 대기를 표시합니다.
토픽 목록의 표시 이름은 기존 이름을 유지하고, ROS bag 카메라 Hz는 재생 소스에서
측정합니다. 실시간 영상으로 자동 전환하지 않습니다.

카메라 토픽을 선택하고 OFF 버튼으로 켭니다. 기본은 꺼짐이며 FPS 기본값은 15입니다.
FPS는 5, 10, 15, 20, 25, 30만 선택할 수 있습니다. 선택값에 따라 H.264 비트레이트
예산은 각각 600, 900, 1200, 1400, 1600, 1800 kbps로 자동 적용됩니다.
카메라 옆 Hz는 브라우저에 실제 표시된 프레임 기준입니다. 영상 형식·해상도·예산과
현재 세션의 평균 영상 kB/s도 표시합니다. 실제 표시 FPS는 원본 FPS와 네트워크에 따라 낮을 수 있습니다.

main의 `tools/dashboard_camera.py`는 요청한 영상만 구독합니다. 압축 JPEG는 추가 손실 압축 없이
차량 내부 HTTP로 전달하고, 비압축 Image는 로컬 전달용 JPEG로 변환합니다.
dashboard의 시청자별 인코더가 최대 640×360으로 비율을 유지해 축소하여 H.264/fMP4로 전송합니다.
인코딩은 웹 이벤트 루프와 분리되며, 입력은 최신 프레임 하나만 보관합니다.
서로 다른 시청자의 FPS는 각자의 인코더에 적용합니다. JPEG 원격 전송으로 자동 대체하지 않습니다.

기존 SSH/Tailscale의 HTTP 포트 전달을 사용하며 별도 미디어 포트나 외부 서비스는 필요 없습니다.
브라우저는 MSE/H.264를 지원해야 합니다. SourceBuffer ACK, 제한된 전송 창, 짧은 재생 버퍼와
최신 위치로 맞춤으로 오래된 영상의 누적을 제한합니다. FPS 변경 시 영상 세션만 새로 시작하고
bag 재생 배속·프로세스와 GPS 이력은 유지합니다.
카메라 OFF, 백그라운드 탭, ROS Bag 보기 이외의 모드에서는 영상 요청을 중단합니다.

`config.yaml`의 camera.fps와 max_width는 초기 설정입니다. max_width는 전송 시 최대 640으로
제한합니다. jpeg_quality는 이전 설정 호환을 위해 남아 있으며 원격 H.264 품질을 결정하지 않습니다.
코덱 의존성은 dashboard 이미지의 `av==17.0.1`에 고정합니다.

대시보드 토픽 수집은 허용 목록으로 제한하며 LiDAR 토픽은 구독·표시·전송하지 않습니다.

main이 실행 중이지 않으면 카메라와 토픽 상태는 수신 대기입니다.

## 데이터 사용량

화면에는 차량 노트북의 **핫스팟 인터넷 사용량 추정치** 하나만 표시합니다.
누적 / 초당 / 시간당 예상 형식은 유지하며 대시보드 별도 행, 접속 선택창은 없습니다.
외부 시청 노트북이나 휴대폰 자체/다른 연결 기기의 사용량을 합산하지 않습니다.

기존 Wi-Fi 인터페이스의 전체 송수신 바이트 대신, `dashboard/internet_meter.py`가
물리 인터넷 인터페이스를 지나는 IPv4/IPv6 패킷의 상대 주소와 IP 길이를 확인합니다.
공인 상대 주소와의 송수신을 합산하고 사설·링크로컬·멀티캐스트 및 해당 인터페이스의
직접 연결된 서브넷은 제외합니다. Docker/localhost/ROS 탐색은 제외하고,
인터넷 다운로드·업로드·SSH·Tailscale은 물리 인터페이스의 실제 외부 패킷으로 한 번 셉니다.
IP 헤더, ACK, 관측한 TCP 재전송은 포함합니다. 패킷 내용·주소 로그는 저장하지 않습니다.

기존 `dashboard` 컨테이너 안에서 `python -m dashboard.launch`가 계측기와 웹서버를
함께 실행합니다. 별도 컨테이너나 호스트 프로그램은 필요 없습니다.
컨테이너는 host 네트워크와 NET_RAW를 사용하며, SETUID/SETGID는 웹서버를
기존 UID/GID 10001로 낮추는 데 사용합니다. 웹서버는 패킷 계측 권한 없이
127.0.0.1:${DASHBOARD_PORT:-8080}에서만 수신합니다. Docker 소켓, NET_ADMIN,
방화벽 변경은 사용하지 않습니다. 바이트 합계만 `/traffic/internet.json`에 원자적으로
갱신하며 이 경로는 메모리(tmpfs)이고 컨테이너를 재생성하면 지워집니다.

인터페이스는 IPv4/IPv6 기본 경로의 물리 장치로 자동 선택합니다.
고정하려면 `.env`에 `DASHBOARD_UPLINK_INTERFACE=wlp0s20f3`처럼 지정하세요.
유선/다른 인터넷 경로로 전환하면 자동 선택 대상도 바뀌므로 핫스팟만 측정하려면 고정합니다.
수집이 끊기거나 통계가 5초 이상 오래되면 오류와 —를 표시하며,
기존 Wi-Fi 전체 합계로 몰래 대체하지 않습니다. 커널 캡처 누락도 오류로 표시합니다.

**통신사의 실제 과금량과 동일한 수치는 아닙니다.** 휴대폰의 DNS/프록시 대행,
사설 주소의 통신사 서비스, 패킷 오프로딩, 손실 및 통신사별 집계 규칙은 정확히
재현하지 못합니다. 같은 LAN에 공인 주소가 있으면 직접 연결 서브넷 기준으로 제외하지만
복잡한 라우팅/프록시 환경에서는 추가 차이가 생길 수 있습니다. 실제 차감량은
휴대폰의 기기별 테더링 통계나 통신사 자료와 비교해야 합니다.

누적은 웹서버 측정 시작 이후, 초당은 실제 표본 간격의 증가량 / 경과시간,
시간당 예상은 최근 N개 초당 값 평균 × 3,600입니다. `config.yaml`의
`traffic.smoothing_samples`로 N을 설정합니다. 새로고침으로 초기화되지 않지만
컨테이너/웹서버 재시작 시 초기화됩니다. 지난 1시간의 실측 합계는 아닙니다.

## ROS 토픽

데이터 사용량 아래 박스는 설정에 등록한 모든 토픽 이름과 수신 Hz를 표시합니다.
미수신 토픽도 이름을 유지하고 Hz 자리에 `-`를 표시합니다.

### 토픽 분류 설정

`dashboard/config.yaml` 파일 하나를 편집합니다. 기본 분류는 카메라, 라이다, GNSS,
기타이며 설정에 적힌 순서대로 표시됩니다. ROS 토픽 오른쪽의 `실시간` / `ROS bag`
버튼으로 모드별 토픽 목록과 필수 조건을 선택합니다. 센서/로스백 실행에는 영향을 주지 않습니다.
선택은 브라우저별로 저장되어 새로고침·재접속 후 유지되며 다른 접속자의 선택을 바꾸지 않습니다.
처음 접속하거나 저장된 모드가 삭제된 경우 `default_mode`를 사용합니다.

기본 실시간 모드는 `/camera/image_raw`와 `/camera/image_raw/compressed`가 모두 필수입니다.
ROS bag 모드는 압축 토픽만 필수이며 기존 replay 토픽은 선택 항목입니다.
실시간 라이다 목록에는 현재 `proc_mask: PCL|IMU`에 맞춰 `/lidar/imu`를 포함했습니다.
bag 목록은 기본 녹화 프로필 `2026-09-20`과 현재 사용한 `2026-09-20_5` 기준입니다.
이 bag의 녹화 토픽은 압축 카메라, 라이다 points/metadata, GNSS fix/odom/status,
tf_static의 7개입니다. IMU와 원본 영상은 녹화하지 않았으며, replay 영상은 별도
변환 프로그램이 만드는 출력입니다. `camera_only`, 과거 `run` 등 다른 bag은 녹화 목록이 다릅니다.
`2026-09-20_1`에는 GNSS 토픽 이름만 있고 실제 GNSS 메시지는 0개입니다.

기타에는 `/parameter_events`(파라미터 변경), `/rosout`(로그)을 양쪽에 표시합니다.
실시간의 `/lidar/os_driver/transition_event`는 드라이버 상태 전환 이벤트이며,
bag의 `/events/read_split`은 플레이어의 재생 파일 전환 이벤트입니다.
이들은 주기적인 센서 데이터가 아니므로 새로 추가한 항목은 모두 선택(`false`)입니다.
기존 항목의 필수 여부는 유지했습니다. 각 토픽의 역할은 `config.yaml` 주석에도 적었습니다.

현재 기본 실행에서 꺼진 `/tf`(GNSS `publish_tf:=true`일 때), `/clock`(bag `--clock` 사용 시),
라이다 영상/scan/raw packet/telemetry 및 별도 차선 인식 출력은 기본 목록에 넣지 않았습니다.
추가 실행 시 미등록 수신 토픽은 예외로 표시됩니다.

각 모드의 `groups` 아래에서
분류/토픽/`required`를 독립적으로 편집하면 됩니다. 예:

```yaml
default_mode: live
modes:
  live:
    label: 실시간
    groups:
      - name: 카메라
        topics:
          - name: /camera/image_raw
            required: true
          - name: /camera/image_raw/compressed
            required: true
  bag:
    label: ROS bag
    groups:
      - name: 카메라
        topics:
          - name: /camera/image_raw/compressed
            required: true
```

모드·분류·토픽은 설정 순서대로 표시됩니다. 같은 모드 안에서 분류와 토픽 이름은
중복 등록할 수 없습니다. 서로 다른 모드에는 같은 토픽을 등록할 수 있습니다.
기존 최상위 `groups` 형식도 실시간 단일 모드로 지원합니다. 토픽은 접두사/와일드카드가 아닌
전체 이름으로 정확히 매칭하며, 각 분류 안에서도 설정 순서대로 표시합니다.
선택한 모드 설정에 없는 수신 토픽은 마지막 `예외` 분류로 모읍니다. `예외`는 자동 생성되므로
설정에 추가하지 않습니다.

- `required: true`인 필수 토픽 모두에 유효한 양수 Hz가 있음: 초록불 `정상`.
- 필수 토픽 중 하나라도 미수신/유효기간 만료/Hz 미측정 또는 0: 노란불 `토픽 오류`.
  오류 원인인 필수 토픽 이름 앞에도 노란불을 표시합니다. 정상 수신으로 돌아오면 사라지며,
  선택 토픽과 예외 토픽에는 표시하지 않습니다. 웹 연결 중단 시 필수 토픽 모두에 표시합니다.
- `required: false`인 선택 토픽은 표시만 하며 미수신이어도 정상 판정에 영향을 주지 않습니다.
- `required`를 생략하거나 기존처럼 토픽 이름만 쓰면 필수(`true`)로 처리합니다.
- 설정에 등록한 토픽은 수신 여부와 관계없이 모두 표시합니다. 미수신 토픽이나
  현재 수신 주파수를 계산할 수 없는 토픽의 Hz는 `-`로 표시합니다.
- 필수 토픽이 없는 분류(빈 분류 포함)는 상태를 `-`로 표시합니다.
- `예외`는 정상/오류 판정을 하지 않습니다. 수신 토픽이 없으면 `-`.
- 보관형 토픽도 필수로 지정하면 Hz가 `-`일 때는 토픽 오류입니다. 간헐적으로 발행되는
  `/tf_static`, `/lidar/metadata`는 기본 설정에서 선택 토픽으로 지정했습니다.
  `정상`은 필수 토픽의 양수 Hz 여부 기준이며, 센서 값의 정확성이나 목표 Hz를 판정하지 않습니다.

`config.yaml`이 있는 부모 경로를 읽기 전용으로 연결하고 파일을 매초 다시 읽으므로 저장하면
서버 재시작/재빌드/브라우저 새로고침 없이 반영됩니다. 문법 오류나 중복 등록 시
화면에 설정 오류를 표시하고 마지막 유효 설정을 유지합니다. 웹 연결이 끊기면
등록 토픽 이름은 유지하되 Hz를 `-`로 지우고 등록 분류를 오류 상태로 전환합니다.
예외 분류는 실제 수신된 미등록 토픽만 표시하고 연결이 끊기면 비웁니다.

`docker compose up -d main dashboard`로 실행하면 main의 entrypoint가
`main/tools/dashboard_collector.py`를 자동 실행합니다. 이미 실행 중인 main에는
다음 명령으로 재시작 없이 수집기만 추가할 수 있습니다.

```bash
docker compose exec -d main bash /workspace/docker/entrypoint.sh true
```

수집기는 main과 같은 ROS_DOMAIN_ID와 빌드된 메시지 타입을 사용합니다. 2초마다
퍼블리셔를 발견하고 실제 구독 콜백의 최근 5초 수신 간격으로 Hz를 계산합니다.
메시지가 한 번만 들어오면 주파수를 계산할 수 없어 Hz는 `-`로 표시합니다. 새 메시지 없이
3초가 지나면 일반 토픽은 미수신 처리합니다. 등록된 토픽은 이름을 유지하고 Hz를 `-`로
표시하며, 미등록 토픽은 예외 목록에서 빠집니다.

토픽 통계 수집기는 센서 메시지를 raw 구독으로 main 내부에서만 수신하며, 이름·Hz·마지막 수신 후 경과
시간만 1초마다 로컬 HTTP로 보냅니다. 영상은 별도 카메라 bridge에서 선택 시에만 보냅니다.
구독은 CPU/메모리 및 ROS 통신 부하를 추가하며 표시 Hz는 실제 퍼블리셔 설정값이
아닌 수집기 수신 기준입니다. 일반 토픽은 best-effort / volatile QoS로 수신합니다.
모든 발행자가 TRANSIENT_LOCAL인 보관형 토픽은 해당 durability로 구독해 저장된
메시지도 받습니다. 실제로 한 번 수신한 이후에는 발행자가 유지되는 동안 행을
유지하고, 새 메시지가 없으면 Hz 대신 `-`를 표시합니다. `/tf_static`,
`/lidar/metadata` 같은 토픽의 간헐적 발행으로 행이 깜빡이는 현상을 방지합니다.
발행자가 교체·종료되면 이전 수신 기록을 지우며, 보관형이라도 한 번도 수신하지
않은 토픽은 미수신으로 처리합니다. 지원되지 않는 메시지 타입은 건너뛰고
`docker compose exec main cat /tmp/dashboard-collector.log`에 기록합니다.
QoS 기준: [ROS 2 Humble 문서](https://docs.ros.org/en/humble/Concepts/Intermediate/About-Quality-of-Service-Settings.html).

main이나 수집기가 종료되어도 dashboard는 유지하며, 수집기 보고가 3초간 없으면
보관형을 포함한 수신 상태를 초기화합니다. 이때 등록된 토픽은 이름과 `-`를 표시하고 예외 목록은 비웁니다.
서버는 선택된 모드의 목록·판정과 작은 통계만 동일 WebSocket에 함께 실어 보내므로
추가 폴링은 없습니다. 선택하지 않은 모드의 토픽 목록은 전송하지 않습니다.

## 이전 지도 기능 기록 (현재 화면에서 제거됨)

아래 GPS/LiDAR 설명은 이전 구현 기록입니다. 현재 대시보드에서는 지도 화면 및 브라우저 지도 구독을 시작하지 않습니다.

### GPS 경로 지도 (2026-09-20)

중앙 화면은 인터넷 배경지도 없이 공통 ENU 좌표계에 GPS 경로를 표시합니다.
초기 전체 경로 보기에서 아래의 수신 기반 누적 표시로 변경되었습니다.

공통 원점과 오프라인 분석 데이터를 다시 추출하려면 호스트에서 실행합니다.
Python, PyYAML, zstd가 필요하며 원본 bag은 변경하지 않습니다.
압축 bag은 임시 디렉터리에 하나씩 해제하므로 가장 큰 bag의 해제 크기만큼
임시 공간이 필요합니다.

```bash
python3 dashboard/tools/extract_gps.py
docker compose up -d --build dashboard
```

결과는 `dashboard/data/gps-2026-09-20.json`에 저장됩니다.
첫 유효 fix의 위경도·타원체 높이를 공통 원점으로 사용하며 평면 표시에는
동일 높이를 적용합니다. 웹 요청 중에는 bag을 읽거나 압축 해제하지 않습니다.

### 재생 중 GPS 누적 표시

중앙 지도는 이제 추출된 전체 경로 대신 **현재 ROS `/gnss/fix` 수신값**을
순서대로 누적합니다. 기존 추출 JSON은 공통 원점에만 사용합니다.
09-20(KST) 헤더 시각의 유효 NavSatFix만 표시하며, bag 파일명은 토픽에
포함되지 않으므로 화면에서 특정 bag을 선택하거나 재생하지는 않습니다.
원하는 09-20 bag을 기존 방식으로 재생하면 됩니다. GPS 갱신은 기록 빈도
(약 1Hz)를 따르고, bridge와 웹 전달 지연이 추가됩니다.

`main/tools/dashboard_gps.py`가 GPS와 `/clock`을 구독하며 main entrypoint에서
자동 실행됩니다. 이미 실행 중인 main에서는 아래 명령으로 추가할 수 있습니다.
중복 실행은 파일 잠금으로 방지합니다.

```bash
docker compose exec -d main bash /workspace/docker/entrypoint.sh true
```

재생 시간이 역행하면 수신 세션만 구분하고, 화면의 누적 GPS 점은 유지합니다.
앞으로 건너뛰어 GPS 시각 차이가 3초를 넘으면 선을 끊습니다. GPS가 없는
bag이나 일시정지·종료 시에는 마지막 경로와 수신 대기 상태를 표시합니다.
`경로 지우기`는 해당 브라우저의 표시만 지우고 이후 수신점부터 그립니다.
`자동 맞춤`은 경로 전체를 화면에 맞춥니다. 직접 이동/확대하면 해제됩니다.
현재 마커는 가장 최근 수신 위치이며 보간이나 진행 방향 추정은 하지 않습니다.

서버는 화면 지우기 전까지 GPS 점을 메모리에 누적하며 브라우저에는 새 점만 전달합니다.
재접속하면 서버의 보관 경로를 복구합니다. bridge는 최근 256점을 재전송해
짧은 웹 연결 중단을 복구하고, 복구 불가능한 순번 공백은 선을 끊습니다.
NavSatFix 상태는 Fix/SBAS/GBAS로 표시하며, 이 상태만으로 RTK Fixed/Float를
구분하지 않습니다. 실시간 스트림 전송량도 대시보드 사용량에 포함됩니다.

### LiDAR 실시간 지도 탭

`LiDAR 실시간 지도` 탭은 `/lidar/points`를 차량의 KISS-ICP로 정합한 뒤,
0.5m 격자의 반복 관측 평균점과 추정 궤적을 받아 표시합니다. 원본 점군은 브라우저에
전송하지 않습니다. GPS 보정·루프 폐합 전의 상대 지도입니다. 기존 `_4` 오프라인
지도 파일은 `main/maps/2026-09-20_4_relative/`에 그대로 보관됩니다.

- 정합은 입력 스캔마다 수행하고 지도 키프레임은 이동 0.5m, 회전 3°, 경과 2초 중
  하나를 만족할 때 추가합니다. 같은 격자를 서로 다른 키프레임에서 2회 이상 관측해야 표시합니다.
  키프레임 안의 점들은 먼저 평균하므로 점이 많다는 이유만으로 반복 관측으로 세지 않습니다.
  이후 평균 위치가 마지막 전송 위치에서 5cm 이상 바뀌면 같은 ID의 점을 교체합니다.
  이는 표면 메시 생성이나 움직이는 물체 제거를 보장하는 기능은 아닙니다.
- 브라우저 전송은 1초마다 최대 지도점 추가/교체 3,750개 + 경로점 100개 + 작은 상태 헤더입니다.
  지도점 ID+XYZ는 60,000 bytes/회, 경로점은 최대 1,200 bytes/회입니다.
- 수신 ACK 후 다음 묶음을 보내므로 느린 브라우저에 전송 큐가 무제한 쌓이지 않습니다.
- 다른 지도 탭으로 전환하거나 브라우저 탭이 백그라운드로 가면 LiDAR WebSocket을 닫습니다.
  정합 자체는 계속하며, 다시 열면 현재 지도부터 같은 전송 한도로 복원합니다.
- 지도점 최대 500,000개, 경로점 최대 20,000개를 보관합니다. 한도 도달 시 표시하고
  신규 점 추가를 멈춥니다. 기존 격자의 평균 갱신은 계속합니다. 지도와 경로의 한도는 각각 적용하며 정합은 계속합니다.
- 실시간 지도는 메모리에 보관됩니다. 정합 프로세스 재시작, 재생 되감기, 큰 스캔 공백
  (0.3초 초과), 정합 오류 시 새 지도로 초기화합니다. 일시정지 중에는 마지막 지도를 유지합니다.
- `큐 누락`은 정합기 내부의 8스캔 대기열 초과 횟수입니다. ROS/DDS 전체 누락을 의미하지 않습니다.
- 09-20 재생 범위를 유지하기 위해 최근 3초 안에 `/gnss/fix` 또는 `/clock`에서
  09-20 KST 시각을 확인해야 입력을 처리합니다. GPS는 날짜 확인과 되감기 감지에만
  사용하며 지도 위치를 보정하지 않습니다. GPS가 없는 bag은 `--clock` 재생이 필요합니다.
  중단 후 날짜 확인을 기다리며 스캔 공백이 커졌다면 재개 시에도 지도가 초기화될 수 있습니다.

설치는 main의 카메라/ROS 전역 Python 환경과 분리하며 한 번만 실행합니다.

## 중앙 실시간 GPS 점 표시 (2026-09-24)

rosbag 재생은 사용자가 시작한다. main의 `tools/dashboard_gps.py`가 `/gnss/fix`를 받아 대시보드로 전달한다. 날짜 제한 없이 정상 fix의 위경도를 수신한다. 첫 수신점을 원점으로 하는 ENU 평면도이며, 미터 좌표와 최신 위경도를 표시한다. 평균 묶음/보간/카메라 BEV는 적용하지 않은 원본 측정점 표시다.

배경과 테두리가 없는 투명 canvas에 점을 누적하고 최신 점에 원을 표시한다. 자동 전체 맞춤, 휠 확대, 드래그 이동, 전체 보기 복귀와 화면 지우기를 지원한다. 화면 지우기는 서버와 연결된 화면의 GPS 표시 이력을 비운다. 점 개수에 따른 자동 삭제는 하지 않는다. 새로고침하면 서버에 남은 점을 복원한다. bag 시간 역행은 새 세션으로 구분한다. 수신 중단 3초 후 대기 상태로 표시한다.

ROS Bag 보기의 GPS 지도에는 미터 기준 격자를 표시한다. 확대·축소에 따라 한 칸 간격을 1·2·5 계열로 조정하고, 왼쪽 아래에 한 칸의 실제 거리와 같은 길이의 축척 막대를 표시한다. 격자는 GPS 원점 기준이며 드래그할 때 측정점과 함께 이동한다.

실행 화면에는 자동차·이전 GPS/LiDAR 흰 박스와 지도 탭을 다시 표시하지 않는다. GPS 표시용 코드는 `dashboard/gps-live-overlay.js`, 브라우저 경로는 기존 `/gps.js`다.


## Bag 선택과 GPS 누적

`1. ROS Bag 보기` 모드의 `ros bag 재생`에서 bag을 고르고 `재생`을 누릅니다.
`main/bags/` 아래의 `metadata.yaml`이 있는 녹화 폴더를 재귀적으로 검색하며,
`1017/2026-10-17_1`처럼 상대 경로로 표시합니다. 번호는 숫자 순서로 정렬합니다.
10월 17일 녹화본은 `1017/2026-10-17_1`부터 `1017/2026-10-17_5`까지입니다.
기본은 한 번 재생 후 종료이며, 재생 전에 `반복`을 체크하면 계속 반복합니다.
재생 중에는 선택/반복 변경이 잠기므로 다른 bag은 정지 후 선택합니다.
`main/tools/dashboard_bags.py`가 main 컨테이너 안에서 실행되며 127.0.0.1:8768에서
대시보드 요청을 받습니다. 기존 카메라 QoS를 유지하며 대시보드가 시작한 프로세스만
정지합니다. 터미널에서 따로 실행한 rosbag이 있으면 먼저 종료하라는 상태를 표시합니다.
main 재시작 시 entrypoint가 제어기를 자동 실행합니다.

GPS는 bag 변경/반복에도 같은 첫 좌표 기준으로 누적하며 자동 10000점 삭제를 없앴습니다.
`화면 지우기`는 서버 메모리의 표시 이력을 지우고 연결된 화면에도 반영합니다.
브라우저 재접속/새로고침 시 이력을 다시 받으며, dashboard 컨테이너 재시작 시에는
메모리 이력이 초기화됩니다. GPS 파일 저장은 하지 않습니다.

`/gnss/status`의 NMEA 품질 4(Fixed), 5(Float)는 파란색, 나머지 유효 위치의
비RTK 품질(SPP/DGPS 등)은 빨간색, 품질 미확인은 회색입니다.
NavSatFix.status만으로 RTK를 단정하지 않습니다. UInt8 품질 메시지에는 타임스탬프가
없어 수신 시각 ±0.3초 이내의 가장 가까운 상태를 0.2초 지연 후 연결합니다.
현재 1Hz·1배속 재생에 맞춘 방식이며 심한 전송 지연에서는 미확인/연결 오차가
발생할 수 있습니다. 유효하지 않은 위치(no fix, NaN)는 점으로 표시하지 않습니다.


### Bag 배속

`−0.1` / `+0.1`로 0.1배씩 조절하며 현재 적용 배속을 `1.0×` 형식으로 표시합니다.
기본 1.0배, 최소 0.1배입니다. 정지 상태에서는 다음 재생 배속을 설정하고,
재생 중에는 소유한 player의 `set_rate` 서비스로 즉시 반영한 뒤 `get_rate`로 확인합니다.
bag을 다시 시작하거나 GPS 이력을 지우지 않습니다. 준비/정지 처리 중에는 버튼을 잠급니다.
제어기 재시작 전까지 마지막 배속을 다음 bag에도 사용합니다.

## monitor_1021 경로추종 표시

기존 dashboard 주소의 `/monitor-1021`에서 예정 경로·현재 차량·주행 궤적·PP 목표점을 표시한다.

상태를 구분하고, 수신 중단 시 마지막 정상 위치를 회색 마커와 경과 시간으로 유지한다.
정상 위치 수신 이력이 없으면 원점에 차량 마커를 그리지 않는다. 무효·만료·좌표계 불일치
상태에서는 PP 목표점과 오차를 숨긴다. `전체 경로 보기`와 `현재 차량 따라가기`를 지원한다.
이 화면은 메모리 기반 표시 전용이다.
기록은 별도 `vehicle_recorder`로 실행한다. 기존 GPS 배경맵 표시와 원본 monitor는 유지한다.

## GPS 지도 생성의 선택적 MAP 병합 단계 (2026-10-28)

2단계 ROS bag 선택에 `MAP 병합하기` 체크박스를 추가했습니다. 기본값은 해제이며 기존 단계 순서로 진행합니다. 체크하고 2단계를 저장하면 3단계에 MAP 병합하기 비교 화면이 표시되고, GPS 노이즈 제거부터 4~13단계로 진행합니다. 왼쪽에는 2단계에 저장된 로스백 GPS를 표시하고, 오른쪽에는 이 단계에서 검색·다중 선택하여 불러온 로스백 GPS를 표시합니다. 양쪽 지도는 기록별 표시, 드래그 이동, 휠 확대·축소, 전체 보기와 점 좌표 확인을 지원합니다. 오른쪽에서 복사한 구간을 왼쪽 기준 GPS 위에 배치하고 GPS 노이즈 제거로 진행할 수 있습니다. 4단계부터는 배치한 구간만 작업 입력이며, 왼쪽 기준 로스백은 연한 배경 점으로 표시합니다. 설정은 맵 파일별로 저장되어 다시 불러와도 유지됩니다.

기존 맵 파일과 GPS 편집 API의 단계 키는 유지합니다. 선택적 단계에 따라 화면 번호와 저장 파일명 번호를 조정하며, 설정은 `stages["2"].map_merge`에 보존합니다.

오른쪽 비교용 GPS는 기존 `replay-prepare`/`replay-status` 읽기 API로 불러오며 2단계 원본 추출 파일이나 저장된 맵의 GPS를 바꾸지 않습니다. 오른쪽 비교 로스백 선택과 클립보드는 현재 화면에서 유지되며 다른 프로젝트를 열면 초기화됩니다. 확정한 배치 구간은 맵 작업 파일에 저장되어 다시 불러올 수 있습니다. 여러 로스백 중 일부를 읽지 못한 경우 성공한 기록과 실패 사유를 표시하고, 전부 실패하면 이전 비교 지도를 유지합니다.

MAP 병합 비교 화면 상단의 `같은 스케일로 보기`를 누르면 양쪽 표시 기록을 각각 전체 보기로 맞춘 뒤, 모든 기록이 보이는 공통 축척(화면 픽셀/미터)을 적용합니다. 양쪽에 표시할 GPS가 있을 때 사용할 수 있으며, 각 지도는 이후 개별 확대·이동이 가능합니다.

오른쪽 지도에서 같은 기록의 서로 다른 두 점을 클릭한 뒤 `선택 구간 복사` → `왼쪽에 붙여넣기`를 누릅니다. 양 끝점을 포함한 연속 구간이 원본 순서로 복사되고 왼쪽 지도 중심에 붙여넣어집니다. 보라색 구간이나 선을 왼쪽 버튼으로 드래그하면 형태와 점 간격을 유지한 채 평행이동합니다. 빈 곳 또는 오른쪽/가운데 버튼 드래그는 지도 이동입니다. 여러 구간을 배치할 수 있으며 선택 배치 삭제와 최근 배치 변경 실행 취소를 지원합니다.

`배치 확정·저장` 또는 `저장 후 GPS 노이즈 제거`로 배치를 저장합니다. 다음 단계로 이동할 때도 자동 저장하며, 이동·회전한 배치 구간만 후속 노이즈 제거·포인트 추가·병합·최종 경로 생성에 사용합니다. 기준 로스백은 2단계 원본으로 보존하며 작업 입력이나 최종 맵에 포함하지 않습니다. 2단계 원본은 보존하고 `map_merge_result`에 원본 구간·이동량·후속 단계용 GPS를 따로 저장합니다. 이동한 점에는 원래 위치의 카메라 연결을 복사하지 않습니다. MAP 병합 단계로 되돌아오면 배치를 유지하며 이후 단계 결과를 제거하고, 2단계로 되돌아가거나 MAP 병합을 해제하면 배치 적용도 제거합니다.

붙여넣은 구간을 선택하면 화면 상단의 `회전 °` 입력·슬라이더, `−1°`·`+1°`, `회전 초기화`로 방향을 조절할 수 있습니다. 구간의 중심(원본 ENU 경계 상자 중심)을 기준으로 양수는 반시계, 음수는 시계 방향으로 회전합니다. 이동 위치와 점 사이 거리를 유지하며, 회전도 배치 실행 취소·저장·재열기·후속 단계에 반영됩니다. 이전에 저장한 구간은 회전 0°로 처리합니다.

MAP 병합 사용 시 4단계 GPS 노이즈 제거부터 포인트 추가, 기록 내·기록 간 병합, 순서 매칭, 경로 생성, 차선 적용, 과제 구간, 최종 검증·저장 지도에 기준 GPS를 배경으로 표시합니다. 배경은 선택·편집할 수 없고 전체 보기에만 함께 포함되며, 지도 이동·확대에 맞춰 같은 좌표계로 표시됩니다. 겹치는 점은 별도 레이어에서 한 번 합성해 항상 불투명도 18%를 유지합니다. MAP 병합을 사용하지 않는 기존 작업 흐름은 원래 GPS를 계속 작업 입력으로 사용합니다.

기존 `map_merge_result`의 원본+배치 혼합 입력은 로드 시 메모리에서 배치 전용 입력(version 2)으로 바꿉니다. 기준 GPS가 포함된 후속 결과는 이력에 보관하고 현재 단계에서 제거하여 4단계부터 다시 계산하게 합니다. 읽기만으로 호스트 파일을 덮어쓰지 않으며 다음 저장 시 반영합니다. 배치 원본, 이동량·회전각과 2단계 원본은 유지합니다. 배치 구간이 없으면 기준 로스백만으로 다음 경로 단계를 진행할 수 없습니다.

### GPS 노이즈 배경 표시

GPS 노이즈 제거를 저장하면 다음 단계부터 작업 단계 선택 아래에 `노이즈 배경 불투명도` 슬라이더가 표시됩니다. 수동 제외와 시작·끝 범위 밖 GPS 점을 회색 배경으로 표시하며, 0%는 숨김, 100%는 진하게 표시합니다. 기본값은 18%이며 브라우저에 기억되어 단계 이동과 새로고침 후에도 유지됩니다. MAP 병합을 사용하면 배치한 GPS에서 제외된 점에 적용합니다. 기준 로스백 배경의 표시 설정은 별개입니다. 노이즈 배경은 선택·편집·전체 보기 범위·경로 계산·최종 출력에 포함하지 않습니다.
# MAP과 현재 위치

중앙 시각화에서 **5. MAP-현재 위치**를 선택하고 MAP 파일을 고르면, 저장된 GPS 포인트와
현재 `/gnss/fix` 수신 위치를 한 평면도에서 볼 수 있습니다. 파일 목록은
`main/decision/script/map_generator/test/review/maps/`의 JSON 파일을 사용하며, 파일을 수정하지 않습니다.

시작점은 **초록색 원**, 끝점은 **주황색 사각형**, 현재 GPS는 **빨간색 마름모**입니다.
시작·끝 좌표는 오른쪽 설정에도 표시합니다. 저장 경로 또는 저장 웨이포인트 순서를 사용하며,
순서 매칭 이전 단계 파일은 파일 순서 기준이라고 표시합니다. 최종 내보내기 파일과 지도 프로젝트 파일을 지원합니다.

MAP과 현재 위치는 지도 첫 GPS 포인트를 공통 원점으로 WGS84 ENU에 투영합니다.
드래그·휠 확대, MAP 전체 보기, 현재 위치 중심 보기, MAP·현재 위치 함께 보기를 사용할 수 있습니다.
GPS는 해당 화면을 열었을 때 0.5초 간격으로 갱신하며 수신이 3초 이상 멈추면 마지막 위치를 회색으로 표시합니다.
GPS 화면 이력을 지워도 최신 수신 위치는 유지합니다. rosbag 재생 중에는 재생된 `/gnss/fix`가 표시되며,
이 화면은 센서나 rosbag 재생을 시작하지 않습니다.


### 최종 웨이포인트 추가

과제 구간 설정 다음의 `최종 웨이포인트 추가`에서 지도 클릭 또는 위도·경도 입력으로 점을 추가합니다. 최종 순번은 1부터 시작하며, 해당 위치에 삽입하면 이후 번호가 자동으로 밀립니다. 추가점은 목록이나 지도에서 선택한 뒤 순번 변경·삭제가 가능하며 되돌리기도 지원합니다. 기존 점들의 상대 순서는 유지됩니다.

추가점은 다시 평활화하거나 보간하지 않고 최종 검증 화면과 Map 저장에 반영됩니다. 저장 버튼 또는 단계 이동으로 작업 파일에 보존하며, 차선·과제 구간 등 앞 단계 결과를 변경하면 이후 추가점과 검증 결과도 무효화됩니다. 기존 작업 파일의 단계 키는 유지하고 화면의 단계 번호만 순서대로 표시합니다(MAP 병합 사용 시 번호 자동 증가).

### 6. MAP 비교하기

중앙 모드에서 **6. MAP 비교하기**를 선택한 뒤 MAP 파일 목록에서 여러 파일을 체크하면 같은 GPS 좌표 기준으로 겹쳐 표시합니다. 파일별 색상과 투명도(0~100%)를 조절할 수 있으며, 웨이포인트와 직선 보간선은 각각 켜고 끌 수 있습니다. 드래그로 이동하고 휠로 확대하며, **선택 MAP 전체** 또는 더블클릭으로 전체 범위를 봅니다.

목록은 `test/review/maps`의 JSON 파일을 사용합니다. 프로젝트 파일은 7단계 GPS 순서와 유효한 8단계 웨이포인트 편집을 반영하며, 최종 MAP 파일은 저장 포인트를 연결합니다. 8단계의 후륜축 스플라인은 비교에 사용하지 않습니다. 순서가 아직 없는 프로젝트는 파일별 오류로 안내하며, 다른 선택 파일은 계속 표시합니다. 이 화면의 선택과 투명도 조절은 원본 파일을 변경하지 않습니다.

비교 화면에서도 **ros bag 재생** 목록·재생·정지·반복·배속을 사용할 수 있습니다. 선택한 로스백의 전체 GPS 기록은 청록색 경로로 표시하며 경로 투명도를 따로 조절합니다. 로스백 선택은 GPS 기록만 읽고, **재생**을 눌렀을 때 기존 ROS bag 제어기로 재생합니다. 현재 `/gnss/fix` 위치는 빨간 마커로 표시하고, 3초 이상 수신이 없거나 연결이 끊기면 마지막 위치를 회색으로 남깁니다. **현재 GPS 따라가기**와 **현재 GPS로 이동**을 사용할 수 있으며, 표시를 끄거나 비교 모드를 벗어나면 현재 GPS 조회를 멈춥니다.
